# QueryHive 0.2.3

A small release on top of 0.2.2: a SQL formatter, tidier SQL when you open a table, and three
fixes for things that stopped working in the editor and the Export button.

## In this release

**Format SQL.** Edit > Format SQL (⇧⌘L, or ⌃⇧F in the DBeaver key scheme) and an item at the top of
the editor's right-click menu lay a query out one clause per line. It formats the statements your
selection touches, or the whole query when nothing is selected, and ⌘Z undoes it in one step. It
only moves whitespace and changes the case of keywords: strings, comments, quoted names and
parameters are left exactly as they were. If it cannot read part of the text it says which line
and leaves everything untouched. Keywords are always written in upper case (MySQL is left as you
typed it), whatever the "auto-uppercase" setting says.

**Opening a table.** The SQL that opens in the tab is already laid out: `SELECT *` and
`FROM <table>` on two lines, and once the first run succeeds, one column per line, indented. Names
are quoted exactly as before. A single column stays on one line, as Format SQL would write it.

**The editor went blank after changing a setting.** Turning "Show invisible characters" or
"Highlight current line" on or off while text was on screen made all the text disappear until the
tab was reopened. The text container was left zero points wide. This has been there since 0.2.0.

**The Export button.**

- It no longer greys out when you close the wizard with its settings unfinished (an empty file
  name, no folder, a table target without a schema). The button only opens the wizard, so only
  "no connection", "no SQL" and "a query is running" disable it now. The wizard's own Export button
  still waits for those settings.
- Pressing Export while the wizard is open closes it, and the next press opens it again, instead
  of sometimes leaving the button doing nothing.

**Open Quickly.** A history entry for a formatted statement was titled `SELECT *` or `SELECT`,
so a table name could not be found. The title is now the whole statement on one line.

## Known issues

- The two Export fixes come from reading the code and from tests with a stand-in window; the
  button was not seen failing in the real app, so tell us if it still does. If it ever does not
  respond, note whether it looks dimmed and what its tooltip says.
- The live database checks (the Trino, PostgreSQL and MySQL containers) were not run for this
  release. Format SQL and the open-table text were checked with automated tests only, and no
  screenshot of Format SQL in the real window was taken.
- ⇧⌘L is also the key of the macOS "Search With Google" service. Inside QueryHive it should run
  Format SQL instead, but that was not checked in the real app.
- With "Show invisible characters" on, spaces get a marker but tabs and line ends do not. That was
  already so in 0.2.2.
- Saving a result to a table on another connection is still in the app behind Settings, General,
  "Experimental: save to a table on another connection". It is off and has never run against a real
  database.
- Everything listed as known in 0.2.2 still applies.

## Installing

`QueryHive-0.2.3-arm64.dmg` is signed but not notarized, exactly as 0.2.2 was. On first launch,
**right-click the app and choose Open**, or use System Settings → Privacy & Security → Open Anyway.
After that it behaves normally, and updates install themselves.

- `QueryHive-0.2.3-arm64.dmg`: the app
- `appcast.xml`: the update feed the app reads; it has to stay attached to this release
