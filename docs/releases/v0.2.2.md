# QueryHive 0.2.2

A fix-heavy release. The main window works properly on macOS 27 again, the connection form is
rebuilt around four sections, and the editor's suggestions know much more about the statement you
are writing. Opening a table, Save to Table and Trino queries ending in `;` were fixed too.

## In this release

**The window.**

- The close, minimize and zoom buttons are back on macOS 27. QueryHive is built against an older
  SDK, so macOS runs it in compatibility mode, and there a custom window background hid them. The
  window no longer sets one of its own. One side effect: while you drag the window edge, a thin gap
  may briefly show the system color.
- The tab strip no longer starts above the top of the window. With no connections saved, the empty
  sidebar asked for more height than a short window had and pushed the strip out of view.
- Tabs can be clicked when the rows are maximised, and in full screen. In full screen the toolbar
  now shows only when the pointer touches the top edge, as in Safari (macOS 15 and later).
- Export opens again when the rows fill the window. Before, its click did nothing until you
  brought the editor back, which looked like Export only worked after minimizing.

**The connection form.**

- It is now four sections (General, SSH Tunnel, Limits, Appearance) beside a sidebar, with the
  Test, Cancel and Save buttons in a footer.
- The encryption control sits right beside Host and uses the same words for Trino, PostgreSQL and
  MySQL. A connection that is stored without certificate checks is labelled "unverified" so you can
  see it.
- Long explanations moved behind a "?" next to the label. It opens when the pointer rests on it,
  and Esc closes only that popover instead of the whole form.
- A saved connection no longer opens as "Unsaved changes", and opening one no longer selects the
  Name field, so the first keystroke does not replace the name.
- The footer and the sidebar name what is missing before you press Save, and Save or Test jumps to
  the first section with a problem. A Test result goes away when you edit the form it described.
- A Trino connection that uses a JWT login with plain HTTP is now flagged before you save it,
  because the engine would refuse it at connect.

**The results and the sidebar.**

- No row shows through the header while a result scrolls.
- Each row in the sidebar has one chevron, not a stack of them, and the grey hover highlight no
  longer stays on rows after you scroll.

**The editor.**

- A trailing `;` now works on Trino. Run, Run with a selection, Export and the MCP run all failed
  with a syntax error on a query ending in `;`.
- Suggestions open more often. A single character is enough where a name is expected, an
  apostrophe in a comment or a quoted name no longer switches them off for the rest of the file,
  and a bare word looks through the tab's own catalogs, schemas and tables without waiting for you
  to expand them in the tree. They stay inside the tab's own connection.
- Suggestions know the statement: `alias.` and `table.` offer that table's columns, a column in a
  SELECT list, WHERE, ON, GROUP BY, HAVING or ORDER BY ranks the statement's own tables first, and
  a CTE offers its declared columns.
- Suggestions load what they need in the background. Table columns are read from the server's
  catalog (so views work), at most three at a time, quietly, and nothing shows if one fails. A
  connection through an SSH tunnel is not touched until something you did has connected through it.
- Names are written quoted exactly when the dialect needs it: a hyphen, a space, upper case, a
  leading digit or a reserved word. Hyphenated schema names such as `prod-ops-x` now complete
  as `"prod-ops-x"` (a backtick on MySQL), while plain names stay bare.
- The suggestion list only acts on the text it was built for. Before, pressing Left and then Tab
  could write a row over the word before the caret.

**Opening a table from the tree.** Double-click, Return, Open in the context menu and the Open
button now write the table's column list instead of `SELECT *`, in the table's order and quoted
only where needed. The tab still runs `SELECT *` once, and the list replaces it only after that
run succeeds. A failed or stopped run, and a table with more than 200 columns, keep `SELECT *`.

**Save to Table.** The button works again on PostgreSQL and MySQL. It asked for target parts those
drivers do not have, so it stayed dim with a reason you could not act on. It now asks only for the
parts the driver has (MySQL calls it the database).

**Safer SQL and imports.**

- Names the app writes into SQL are quoted by the same rule everywhere (the tree, completion,
  write-back and the inspector), a quote inside a name is doubled, and a name with an accent mark
  that was combined from two characters can no longer slip out of its quotes.
- MySQL string literals the app builds now escape backslashes, and a database name can no longer
  end its own literal and add a second statement.
- Importing PostgreSQL or MySQL connections keeps certificate verification on for the modes that
  ask for it, and re-importing a connection that asked to verify turns the check back on. The
  import summary says what each connection needs.
- The row count of a query that ends in a `--` comment no longer fails with a syntax error.

**Save to a table on another connection (experimental, off).** The code for running a query on one
connection and creating its table on another (PostgreSQL, MySQL or Trino to PostgreSQL or MySQL)
is in this release, behind a switch in Settings, General, "Experimental: save to a table on
another connection". It is off, and with it off nothing about Save to Table changes. It has been
tested with stand-in servers only, never against a real database, so leave it off unless you are
trying it on data you can lose. A sheet always names both connections before anything is written,
and the destination connection's own Safe Mode decides what is allowed.

**Building from source.** `app/build-ffi.sh` and `app/build.sh` honour `CARGO_TARGET_DIR` (use an
absolute path), so the bindings come from the library you just built.

## Known issues

- The live database checks (the Trino, PostgreSQL and MySQL containers) were not run for this
  release. The Trino `;` fix, Save to Table, suggestions and opening a table were checked with
  automated tests and stand-in servers, not against real databases.
- On macOS 14 the full-screen toolbar can still cover the tab strip. The fix needs macOS 15 or later.
- Trino still rejects `;;;` and routine bodies that end in `END;`. Only one trailing `;` is removed.
- A new Trino connection defaults to HTTPS on port 8080. Change it to 8443, or to HTTP, as your
  server needs.
- PostgreSQL and MySQL connections that were imported before this release without certificate
  verification keep running without it. The form labels them "unverified", but it does not change
  them; import them again, or turn the check on in the form.
- A suggestion's read of a table's columns can run up to 15 seconds on the server before it stops
  by itself.
- Save to Table: a connection with a blank default schema cannot reopen the wizard to fill it in,
  and the footer tooltip still says Trino for every driver.
- A very fast fling through a result may show one blank frame under the header.

## Installing

`QueryHive-0.2.2-arm64.dmg` is signed but not notarized, exactly as 0.2.1 was. On first launch,
**right-click the app and choose Open**, or use System Settings → Privacy & Security → Open Anyway.
After that it behaves normally, and updates install themselves.

- `QueryHive-0.2.2-arm64.dmg`: the app
- `appcast.xml`: the update feed the app reads; it has to stay attached to this release
