# QueryHive 0.1.0

The first release that can replace itself.

## In this release

**Self-updates.** The app carries Sparkle: it reads an appcast from this repository's latest
release, verifies what it downloads against an EdDSA key, and installs and relaunches itself.
`Check for Updates…` is in the app menu, and a scheduled check runs in the background. 0.1.0 is the
first release that can receive updates — 0.0.1 cannot, so a copy of it has to be replaced by hand.

**Result grid.** Cells can be edited and staged, with the update statements the edits imply; a
selection can be copied out; the footer can ask the server for the real row count instead of the
rows it happened to receive.

**Empty results say which they are.** A grid body with no rows now distinguishes a run that is
still arriving from a statement that matched nothing from a filter that hid everything it did
match, instead of standing a header over a blank panel. A tree row that holds nothing no longer
shows the loading spinner it used to share with `Loading…`.

**Postgres: every database.** A Postgres connection can list all the databases this user may open —
a switch in the connection editor, or `Show All Databases` in the tree's context menu — and then
start at the schemas under the one it names.

**Trino: polling and timeouts.** A queued page is polled on a backoff (10ms, doubling to 200ms)
rather than every half second, which used to cap a healthy query at two pages a second. The connect
phase is bounded at ten seconds, so a wrong port fails instead of leaving the Test button spinning.

## Installing

The app is ad-hoc signed and not notarized, so macOS blocks the first launch once: **right-click the
app in Applications and choose Open**, or use System Settings → Privacy & Security → Open Anyway.
After that it behaves normally, and updates install themselves.

- `QueryHive-0.1.0-arm64.dmg` — the app
- `appcast.xml` — the update feed the app reads; it has to stay attached to this release
