# QueryHive 0.2.0

The release where the grid, the editor and the engine stopped being a prototype and started
carrying the app. 225 commits since 0.1.0: 78 features, 38 fixes, 25 performance changes.

## In this release

**The result grid is a real table.** It is drawn with `NSTableView` instead of a SwiftUI grid, so a
result of hundreds of thousands of rows scrolls and sorts without rebuilding itself. Columns can be
resized, auto-fit and Fit-All'd, hidden, moved and renamed; there are presets and undo; search runs
across columns and sort and search go to the server first. There is a record view that reads one row
as fields, a peek panel beside the grid, a value reader, and a JSON tree and hex view for structured
cells. Per-column display formats apply in the grid. NULL and clipping render correctly. Freeze, the
grid palette and a theme-contrast pass keep every theme legible.

**Results live in Rust, not in Swift.** A `ResultHandle` over UniFFI serves Arrow chunks with a
lossless value mapping; the grid reads windows out of the store rather than holding rows in memory,
and spill is encrypted with a per-process key. This is what makes large results and long sessions
survivable.

**An engine host with a session pool.** Connections are leased, and a session is reset every run so
one tab's transaction cannot leak into the next. Capped previews keep their session (so a cancelled
preview is settled rather than silently re-sent), a sent statement is never sent twice, and Stop
reaches the server. One runtime per process. `mimalloc` is the Rust global allocator. PostgreSQL
exports and large previews use `COPY TO STDOUT`; drivers hand rows straight into the store's columns.

**The editor.** Tree-sitter colours and folds, one tree per statement, applied as temporary
attributes — reaching 2M characters without whole-document work per keystroke. Bracket pairs that
ignore strings and comments; format SQL and toggle line comments through the engine; find bar and
statement folding; a formatter that only ever changes whitespace and keyword case. The server's
error position marks the exact characters it named, and errors are selectable and copyable.

**Import, export and changes.** An import sheet with JSON, JSONL, `.sql`, CSV and streamed XLSX;
value rules (decimal/grouping separators, date and time zones, shortest-form number round-trips, a
refusal rather than a guess when a locale is ambiguous); CSV encoding pre-scan; `ON_ERROR=commit`
never claims rows a commit lost. Exports never clobber an existing file and long exports report
progress in the Dock. A verified apply-changes path with a match policy, a partial-commit
vocabulary and a batch budget.

**Connections and transport.** Import from DBeaver and DataGrip, and export or import QueryHive's
own list. Per-connection CA and credential-origin rules in the drivers. SSH: `ssh_config` aliases, a
known-hosts trust core that never accepts a changed key, first-use pinning, and the tunnel half of
PostgreSQL over TLS with a connect timeout. A host-key sheet that refuses a changed key.

**Safety and access.** A confirmation level, a strictness floor and a tamper-evident execution log.
Safe Mode reads PostgreSQL, MySQL and Trino with their own lexers, and the server enforces
read-only where it can. A server-enforced statement timeout. A read-only MCP server with hashed
tokens, tool scope and a connection allowlist.

**The app around the surfaces.** A native split view and toolbar; an outline object tree the
keyboard and VoiceOver can walk; Open Quickly; query history, saved queries, favourites and session
restore; Google sign-in and profiles; appearance as whole looks with Custom; a TablePro-shaped
settings bar; tab management and a startup preference. Accessibility throughout: nothing a person
must read is smaller than 11pt, tabs are buttons, icons have names, focus and VoiceOver keep up, and
motion and glass follow the system.

## Fixes worth naming

- A Trino preview whose cancel the coordinator refuses is no longer reported as a clean reset — the
  failure surfaces so the session is closed, not parked with a live query on it.
- A Trino `replace` builds the new table beside the old and swaps it in, instead of dropping first.
- Ragged Trino rows are padded or kept, never cut.
- One MySQL session keeps one connection, so one transaction is one transaction.
- Side-effect functions are never treated as a read, and `ANALYZE` cannot persist a write.
- A routine body is one statement, and client-only directives are refused before connecting.
- Stopped runs say they stopped and keep their rows.

## Performance

Stop went from 28.5 s to 28 ms; a keystroke from 669 ms to 13 ms. The grid stays mounted across runs
and paints its first rows sooner. The editor was rebuilt on TextKit 1 on purpose: folding lives in
the layout manager and no whole-document work happens per keystroke. The grid computes displayed
rows once per change, not once per read.

## Installing

`QueryHive-0.2.0-arm64.dmg` is signed but not notarized, exactly as 0.1.0 was. On first launch,
**right-click the app and choose Open**, or use System Settings → Privacy & Security → Open Anyway.
After that it behaves normally, and updates install themselves. A copy of 0.0.1 still has to be
replaced by hand.

- `QueryHive-0.2.0-arm64.dmg` — the app
- `appcast.xml` — the update feed the app reads; it has to stay attached to this release
